# Хочу работать в ..!

## Назначение решения

**Хочу работать в ..!** - MAX-бот для школьников 9–11 классов. Он помогает в одном диалоге выбрать потенциального работодателя и карьерное направление, спланировать экзамены и поступление, пройти путь до практики или стажировки и подать заявку на работу. Пользователю не нужно самостоятельно сопоставлять интересы, ЕГЭ, образовательные программы, вузы и возможности компаний на разных сайтах: бот использует единый каталог и показывает внешние ссылки там, где действие необходимо выполнить на стороне вуза или работодателя.

## Основной пользовательский сценарий

1. Школьник открывает бот, получает короткую справку о командах `/start`, `/restart`, `/roadmap` и `/feedback`, затем отвечает, знает ли он компанию, в которой хотел бы работать.
2. Он указывает класс, регион и готовность учиться в другом регионе. Если компания ещё не выбрана, бот задаёт вопросы о крупной сфере интересов и любимых школьных предметах, показывает подходящие компании с описаниями и предлагает выбрать одну из них. Если компания известна, пользователь сразу выбирает её из каталога.
3. Бот показывает доступные карьерные направления компании с понятными описаниями. Для 9–10 классов затем предлагаются наборы ЕГЭ; для 11 класса учитываются уже выбранные ЕГЭ и ожидаемые диапазоны баллов. Перед созданием цели бот проверяет цепочку «ЕГЭ → ОП/вуз → возможность работодателя» с учётом географии, чтобы не предлагать заведомый тупик.
4. После подтверждения цели создаётся roadmap. В нём сначала есть общие шаги: выбрать и подготовить ЕГЭ, сдать их, подобрать вуз и образовательную программу, подать документы, поступить и учиться.
5. После фактических результатов ЕГЭ пользователь вводит баллы. Бот показывает совместимые ОП и вузы, их проходные баллы и ссылки на сайты. Школьник выбирает до пяти вузов и до пяти программ в каждом, подтверждает подачу документов и позднее отмечает факт зачисления.
6. После поступления roadmap ведёт к возможности выбранной компании - практике, стажировке или проекту. Бот сообщает минимальный курс, формат и даёт ссылку на сайт работодателя. Пользователь подаёт заявку сам и отмечает это в боте. При отказе бот предлагает другую доступную возможность той же компании.
7. Финальный шаг - подать заявку **на работу** в выбранную компанию. После подтверждения roadmap становится завершённым. Статусы и сообщения работодателя пользователь видит по `/feedback`, а сохранённый путь и следующий шаг - по `/roadmap` даже после перезапуска бота.

## Состав и архитектура

Локальное решение состоит из двух Docker-сервисов:

- `efr_bot` - один Go-процесс: MAX-бот, HTTP API, GORM-доступ к данным и планировщик напоминаний;
- `postgres` - PostgreSQL 16: каталог, профили, цели, roadmap, планы поступления, попытки стажировок и история feedback.

```text
Администратор / работодатель ── REST API ──┐
                                            v
MAX-пользователь <── бот и сервисы <── GORM / PostgreSQL
     ^                                      |
     └── push о feedback (best-effort) ─────┘
```

Основные каталоги:

- `handlers/` - диалоги, кнопки и команды MAX-бота;
- `services/` - сценарии профориентации, поступления, roadmap и feedback;
- `repositories/` - запросы к PostgreSQL через GORM;
- `models/` - модели данных;
- `database/` - подключение, `AutoMigrate`, справочники и seed-каталоги;
- `employerapi/` - HTTP API, Bearer-аутентификация и роли;
- `reminders/` - напоминания по активным roadmap;
- `integration/` - интеграционные тесты PostgreSQL.

## Требования, зависимости и внешние интеграции

Для локального запуска нужны Docker Desktop с Docker Compose, токен MAX-бота и токен bootstrap-администратора API. Для запуска без Docker дополнительно нужны Go `1.26.5` и PostgreSQL.

Используемые зависимости:

- PostgreSQL `16-alpine`;
- Go `1.26.5`, GORM `1.31.2` и драйвер PostgreSQL GORM `1.6.3`;
- MAX SDK: `maxbot` и `max-bot-api-client-go/v2`;
- `robfig/cron/v3` для напоминаний и `godotenv` для загрузки `.env`.

Внешние интеграции: MAX Bot API, Docker Hub (первичная загрузка образов), `gu-st.ru` (доверенные корневые сертификаты при сборке образа), а также сайты вузов и работодателей по ссылкам из каталога. Автоматической интеграции с HR-системами, вузами или сайтами подачи заявок нет.

## Переменные окружения

Скопируйте `.env.example` в `.env`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | пусто | Обязательный токен MAX-бота. |
| `ADMIN_API_TOKEN` | пусто | Токен bootstrap-администратора; при старте создаёт или обновляет аккаунт `bootstrap-admin`. |
| `EMPLOYER_API_PORT` | `8080` | Порт HTTP API в контейнере и на хосте. |
| `EMPLOYER_ALLOWED_ORIGIN` | пусто | Единственный разрешённый CORS origin, например `http://localhost:3000`. |
| `REMINDERS_ENABLED` | `true` | Включает еженедельные напоминания. |
| `REMINDER_CRON` | `0 10 * * 1` | Cron из пяти полей; по умолчанию понедельник, 10:00. |
| `REMINDER_TIMEZONE` | `Europe/Moscow` | IANA-таймзона напоминаний. |
| `POSTGRES_DB` | пусто | Имя БД базового Compose-контура. |
| `POSTGRES_USER` | пусто | Пользователь PostgreSQL базового контура. |
| `POSTGRES_PASSWORD` | пусто | Пароль PostgreSQL базового контура. |
| `POSTGRES_PORT` | пусто | Порт PostgreSQL базового контура. |
| `POSTGRES_DB_TEST`, `POSTGRES_USER_TEST`, `POSTGRES_PASSWORD_TEST` | зависят от основных значений | Отдельные имя БД и учётные данные для автоматических тестов. |
| `DB_HOST`, `DB_PORT`, `DB_NAME` | `localhost`, `5432`, `employer_first_roadmap` | Параметры прямого подключения при запуске без Compose. |
| `DB_USER`, `DB_PASSWORD`, `DB_SSLMODE` | `efr`, `efr_local_password`, `disable` | Учётные данные и SSL-режим прямого подключения. |

`docker-compose.yml` фиксирует рабочий режим `main` и загрузку основного
каталога. Варианты значений для `.env`, включая параметры тестовой БД, приведены
в презентации проекта: перед запуском скопируйте нужный набор значений в `.env`.

Минимальный `.env`:

```env
BOT_TOKEN="ваш_токен_MAX"
ADMIN_API_TOKEN="длинный_случайный_секрет"
EMPLOYER_API_PORT=8080
POSTGRES_DB="имя_базы_данных"
POSTGRES_USER="пользователь_БД"
POSTGRES_PASSWORD="пароль_БД"
POSTGRES_PORT=
POSTGRES_DB_TEST=${POSTGRES_DB}_test
POSTGRES_USER_TEST=${POSTGRES_USER}_test
POSTGRES_PASSWORD_TEST=${POSTGRES_PASSWORD}_test
```

## Порты

| Порт | Контур | Назначение |
| --- | --- | --- |
| `EMPLOYER_API_PORT/tcp` | хост | REST API и `GET /healthz`; в примерах `8080`. |
| `5432/tcp` | внутренняя Docker-сеть | PostgreSQL приложения. |

Бот общается с MAX по исходящему HTTPS-соединению, поэтому отдельный входящий
порт для MAX не нужен. PostgreSQL не публикуется на хост: и приложение, и
контейнер `tests` обращаются к ней по внутренней Docker-сети.

## Запуск локальных компонентов

Создайте `.env` из `.env.example` и вставьте в него подходящий набор значений
из презентации проекта. Одна команда поднимает PostgreSQL, MAX-бот и HTTP API:

```bash
docker compose up --build -d
```

Повторный запуск с другими значениями `.env` использует другую БД только при
новом Docker volume. Для отдельного тестового запуска применяйте test-overlay:

```bash
docker compose -p efr_test -f docker-compose.yml -f docker-compose.test.yml up -d --wait postgres
```

```bash
docker compose -p efr_test -f docker-compose.yml -f docker-compose.test.yml run --rm --no-deps tests
```

Проверка запуска:

```bash
curl http://localhost:8080/healthz
docker compose logs -f efr_bot
```

Если в `.env` указан другой `EMPLOYER_API_PORT`, замените `8080` в команде.
Ожидаемый ответ healthcheck: `{"status":"ok"}`.

## Работа с данными

- При старте выполняются `AutoMigrate` и идемпотентный seed обязательных справочников: регионов, интересов и предметов ЕГЭ.
- Базовый Compose загружает основной каталог; повторный запуск обновляет эти данные идемпотентно. Выбранные параметры БД из `.env` определяют используемый Docker volume.
- PostgreSQL хранит общий каталог, профили, выбранные экзамены, цели, roadmap, планы подачи, попытки возможностей работодателей и feedback.
- API-токены сохраняются в БД только как SHA-256-хэши. Исходные `BOT_TOKEN`, `ADMIN_API_TOKEN` и пароль БД остаются переменными окружения.
- Состояние текущего экрана диалога живёт в памяти одного процесса. После рестарта сохранённые roadmap остаются в БД; пользователь возвращается к маршруту командой `/roadmap`.

## API, роли и тестовые данные

Полный контракт всех **49 маршрутов**, схемы и примеры запросов/ответов лежат в [`openapi.json`](openapi.json). Для воспроизводимой API-проверки используйте [`DATA-API.yaml`](DATA-API.yaml), пошаговое пояснение [`docs/api-evaluation.md`](docs/api-evaluation.md) и тела запросов из [`docs/api-test-data.json`](docs/api-test-data.json). Примеры ID в этих файлах нужно заменить ID, реально полученными в предыдущих ответах API. Сгенерированные Bearer-токены не попадают в Git и показываются только при создании или перевыпуске аккаунта.

Базовый локальный URL: `http://localhost:8080`.
Публичный HTTPS-адрес для проверки API: `https://135.106.216.99`.

| Доступ | Ручки и назначение |
| --- | --- |
| Без авторизации | `GET /healthz`. |
| Любой Bearer-токен | `GET /api/v1/me`, `/api/v1/reference-data`, `/api/v1/education-programs`. |
| Только работодатель | `/api/v1/employer/*`: только собственная компания, её направления, связи с существующими ОП, интересы, возможности и заявки. Чужие данные недоступны. |
| Только администратор | `/api/v1/admin/*`: аккаунты, компании, направления, возможности, вузы, ОП, комбинации ЕГЭ, правила и баллы поступления, шаблоны roadmap. |

Все API-маршруты, кроме healthcheck, требуют `Authorization: Bearer <token>`. Работодатель не создаёт вузы, ОП, ЕГЭ или проходные баллы: он выбирает ОП из готового списка и управляет только данными своей компании. Администратор поддерживает весь изменяемый каталог. Справочники регионов, предметов ЕГЭ и интересов доступны только на чтение и поддерживаются seed-данными.

### Порядок работы с тестовыми данными

1. Для проверки полного пользовательского сценария запустите базовый Compose с
   основными значениями `.env` из презентации. Он загрузит актуальный для MVP
   каталог с официальными ссылками и демонстрационными компаниями.
2. Для API-проверки создайте сущности из `docs/api-test-data.json` через
   запросы и роли, описанные в `DATA-API.yaml`. Добавляйте уникальный
   `<run-id>`, сохраняйте ID из ответов и в конце архивируйте записи запросами
   cleanup из фикстуры. Это не затронет основной каталог.
3. Для автотестов внесите тестовые `POSTGRES_*_TEST` из презентации в `.env`.
   Перед чистым прогоном удалите только test-volume командой `docker compose
   -p efr_test -f docker-compose.yml -f docker-compose.test.yml down -v`, затем поднимите
   PostgreSQL и запустите контейнер `tests` командами из раздела запуска.

## Пошаговая ручная проверка на основном каталоге

Перед проверкой поднимите базовый Compose с основными значениями `.env`,
убедитесь в ответе `/healthz` и откройте бот в MAX. Ниже приведены **конкретные
примеры** из основного seed-каталога; можно выбирать и другие доступные
компании, направления, ОП и вузы. Формулировки и порядок карточек могут
меняться при актуализации каталога.

### 1. 9 класс, компания известна

1. Отправьте `/start`; после приветствия ответьте «Да» на вопрос о знакомой компании.
2. Выберите «Лаборатория Касперского», класс `9`, регион «Москва» и нужный вариант готовности учиться в другом регионе.
3. В списке направлений выберите «Специалист по информационной безопасности». Бот сообщает цель и предлагает набор: «Русский язык, Математика (профильная), Информатика».
4. Подтвердите цель. Бот создаёт roadmap из девяти шагов - от подготовки к ЕГЭ до подачи заявки на работу в компании. Команда `/roadmap` показывает цель и следующий незавершённый шаг.
5. Для демонстрации последовательно отметьте подготовку и сдачу ЕГЭ, введите высокие баллы. После результатов бот предлагает, например, ОП «Информационная безопасность» НИЯУ МИФИ, требования и ссылку на сайт вуза.
6. Выберите доступную программу, сохраните план подачи, отметьте подачу, зачисление и обучение. Затем бот покажет возможность по информационной безопасности, курс, формат и ссылку «Подробнее о компании».
7. Отметьте подачу на стажировку/практику, её успешное завершение и финальную заявку **на работу**. Бот показывает экран завершённого roadmap.

### 2. 11 класс, компания известна и ЕГЭ уже выбраны

1. Отправьте `/start` → «Да» → «Яндекс» → класс `11` → «Москва» → «Да, ЕГЭ выбраны».
2. Русский язык бот добавляет автоматически. Отметьте «Математика (профильная)» и «Информатика», затем для каждого предмета выберите диапазон ожидаемого балла.
3. Бот персонализированно сообщает, что с выбранными ЕГЭ и данными профиля в Яндексе доступны направления, например «Разработчик программного обеспечения». Выберите направление и подтвердите цель.
4. В roadmap после шага «Сдать ЕГЭ» введите фактические баллы. Бот предлагает совместимые варианты, например «Прикладная информатика» НИУ ВШЭ или «Программная инженерия» НИЯУ МИФИ, с проходными баллами и ссылками на вузы.
5. Сохраните план поступления и продолжите обычный маршрут до возможности `Young&&Yandex` и заявки на работу. При несоответствии баллов бот не завершает сценарий молча: предлагает повторить ввод или пересмотреть путь.

### 3. 10 класс, компания неизвестна

1. Отправьте `/start`, ответьте «Нет», затем выберите класс `10`, «Москва» и вариант готовности к переезду.
2. На вопрос об интересах выберите «Создавать технологии и работать с техникой», а на вопрос о школьных предметах - «Математика» и «Информатика».
3. Бот показывает ранжированный список компаний с краткими описаниями - среди вариантов, например, Яндекс, VK и Сбер. Выберите Яндекс, затем направление разработки.
4. Бот предлагает жизнеспособный набор ЕГЭ, строит roadmap и показывает будущий маршрут через ОП/вуз к `Young&&Yandex`.

Любимые школьные предметы в полном опросе - мягкий сигнал ранжирования. Они не становятся обязательным набором ЕГЭ и не требуют выбрать ОП, где одновременно есть все отмеченные предметы.

## Примеры ожидаемого поведения

- После создания пути `/roadmap` показывает текущую цель, следующий шаг и кнопку продолжения; после завершения активный roadmap не находится.
- `/feedback` до подачи заявки объясняет, что заявок пока нет; после ответа работодателя показывает статус, сообщение, контакт и историю. Бот пытается отправить push сразу, но история остаётся доступной даже при ошибке доставки.
- Если в регионе нет полного пути, но он есть при переезде, бот объясняет причину и предлагает рассмотреть другие регионы или сменить направление.
- Если изменённый набор ЕГЭ больше не ведёт к ОП и возможности работодателя, бот сообщает это сразу и предлагает изменить ЕГЭ или направление.
- При баллах ниже минимальных требований доступных программ бот предлагает повторный ввод баллов либо пересмотр траектории, а не пустой список.
- При отказе по стажировке/практике бот исключает эту попытку и предлагает оставшиеся подходящие возможности компании; если их нет - корректно возвращает к roadmap.

## Известные ограничения

- Текущий собранный каталог содержит информацию только о Москве. Это осознанный первый контур решения.
- Каталог компаний, ОП, правил ЕГЭ и проходных баллов обновляется вручную через admin API; автоматического получения данных из внешних источников нет.
- Интеграции с HR-системами и автоматической подачи заявки нет. Пользователь самостоятельно переходит по ссылке работодателя или вуза и выполняет действие на внешнем сайте.
- Состояние открытого диалога однопроцессное. Горизонтальное масштабирование потребует общего хранилища состояния.

## Остановка, повторный запуск и очистка

Используйте тот же набор Compose-файлов, что и при запуске.

| Режим | Остановить, сохранив данные | Повторный запуск | Логи | Полный необратимый сброс |
| --- | --- | --- | --- | --- |
| Рабочий запуск | `docker compose down` | `docker compose up --build -d` | `docker compose logs -f efr_bot` | `docker compose down -v` |
| Автотесты | `docker compose -p efr_test -f docker-compose.yml -f docker-compose.test.yml down` | `docker compose -p efr_test -f docker-compose.yml -f docker-compose.test.yml up -d --wait postgres` | `docker compose -p efr_test -f docker-compose.yml -f docker-compose.test.yml logs -f postgres` | `docker compose -p efr_test -f docker-compose.yml -f docker-compose.test.yml down -v` |

`down -v` удаляет Docker volume соответствующего контура и все его локальные данные без возможности восстановления.
